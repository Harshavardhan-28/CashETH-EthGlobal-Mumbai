# AGENTS.md — context for coding agents working on CashETH

Read this before touching the repo. It is written for AI coding agents (Claude Code, Cursor, Codex, etc.) and for humans who have not seen the codebase. `README.md` is the judge-facing document; this file is the working brief.

## 1. What CashETH is

CashETH is agent working capital on **Hedera testnet** (chain id 296), built for ETHGlobal Mumbai (Nov 2026). Prize targets: Hedera "AI Agents That Pay (x402)" and 1inch "Build an Aqua App".

The eight-step flow:

1. A **seller agent** uploads an invoice (a receivable) through the MCP server.
2. The **buyer agent** signs an EIP-712 confirmation (domain `AgentReceivables` / `1`); the seller registers it in `ReceivableRegistry` (duplicate, signature, payee, term, nonce, currency, KYA-level and self-dealing checks are on-chain).
3. The coordinator scores it (`packages/engine` `scoreReceivable`), discovers lender strategies on our redeployed **1inch Aqua** registry, solves cheapest-first, and calls `CreditFacility.openAndFund`, which mints receivable credit notes (RCN) and fills the lenders' strategies through our **modified SwapVM router** (custom `ReceivableCredit` opcode). The facility ends up holding USDC.
4. The seller sets per-worker budgets.
5. **Worker agents** spend through **x402** (`exact` scheme, facilitator `https://x402.org/facilitator`) from 2-of-2 co-signed spend wallets: reserve → pay → commit. The co-signer (engine policy) only signs payments that match an open reservation.
6. A scripted **trader agent** swaps against the lenders' base-yield strategies so swap fees exist ("scripted volume").
7. Hedera Schedule Service (HSS) flips the receivable to overdue / defaulted on time with no cron. **One `scheduleCall` per transaction** is a hard Hedera rule (we hit it: see README §8 and `docs/EVIDENCE.md` "C4 redeploy").
8. The buyer repays `RepaymentRouter`: lenders get principal + fee first, the seller the remainder; reputation counters update in `KYARegistry`.

Lenders are a **shared liquidity** story (never say "pool"): one wallet backs a base-yield strategy (USDC/tUSDT constant product, 30 bps) and a credit strategy with a risk tier (low 700 / medium 850 / high 1300 bps) enforced by the opcode at fill time.

## 3. Running things

Prerequisites: Node 22, pnpm, Foundry (`foundryup`; on some machines `forge` on PATH is Atlassian's CLI, check `forge --version` prints "forge Version"). Secrets live in gitignored `.env` (operator, merchant, USDC ids, facilitator URL) and `.env.accounts` (every demo account, key, EVM address, UAID, topic/NFT ids, spend wallets). Copy `.env.example` and ask the project owner for the real files; never commit them, never print keys.

```bash
pnpm install
pnpm -r build
pnpm -r test                       # TS suites; the aqua anvil project needs FOUNDRY_BIN=<dir with forge/anvil>
cd contracts && forge test         # 181 tests
pnpm -F @casheth/auth-server start # :4020
pnpm -F @casheth/mcp-server start  # :4030  (AGENT_KEYS_IN_PROCESS=true lets the server sign for demo agents)
pnpm -F @casheth/merchant start    # :3003
pnpm demo                          # full lifecycle on testnet, appends to docs/EVIDENCE.md
```

Deploys go through the Hashio relay with `forge script ... --rpc-url https://testnet.hashio.io/api --broadcast --legacy --slow --skip-simulation --gas-estimate-multiplier 130`. Do not redeploy contracts unless the owner asks: the facility address is immutable in the router, repayment router and taker, and every `wire()` is one-shot, so a facility change means redeploying the whole core stack and re-shipping strategies.

## 4. Hedera and 1inch facts that bit us (verified on testnet)

- HTS USDC facade `0x0000000000000000000000000000000000068cDa` (token `0.0.429274`, 6 decimals). `approve(type(uint256).max)` **reverts** (int64 allowances): always approve exact amounts. HTS `approve` needs ~730k gas; estimate can fail, pass an explicit 1M.
- Contracts that receive HTS tokens must associate (`IHRC719.associate()` in constructors). EVM-created contracts auto-associate.
- HSS `scheduleCall` (`0x16b`): **one per transaction**; a scheduled call may schedule the next; a scheduled call runs ~1 s before its expiry so we schedule at threshold + 5 min; the horizon is ~62 days.
- Hashio relay: intermittent 502 and "Failed to save transaction to pool". Retry, but check the mirror node before retrying anything that may have landed (never double-pay). `eth_getLogs` ranges must be ≤ 1,000 blocks. `eth_call` ignores a contract `from`, so dry-run through the real caller.
- Aqua is non-custodial: shipping a strategy does not move funds; lenders keep USDC in their wallet and the router pulls at fill time. One lender balance backs several strategies, so allowances must be raised additively.
- Our SwapVM router drops `XYCConcentrateSwap` to fit EIP-170 (23,759 B runtime). License: `LicenseRef-Degensoft-SwapVM-1.1`, attribution line "Powered by Aqua — © Degensoft Ltd 2025" (see `LICENSE-THIRD-PARTY.md`).

## 5. Conventions

- **Real on-chain only.** No mock data in production paths. Fakes are fine inside unit tests.
- Small, readable functions; reuse `packages/*` helpers instead of copying; comments only where the why is non-obvious.
- TypeScript strict, ESM, vitest. Solidity 0.8.30, via-IR, tests in Foundry.
- Commits: small and meaningful, conventional prefixes (`feat(mcp): …`, `fix(contracts): …`, `docs: …`). **No `Co-Authored-By` trailers.** `main` is pushed after every ~5 commits.
- Every on-chain action gets a HashScan link in `docs/EVIDENCE.md`; `pnpm verify:evidence` checks them against the mirror node.
- Error codes are a typed union in `packages/shared/src/errors.ts` (+ MCP-side codes in `apps/mcp-server`); keep `docs/API.md` in sync.
- Known limitations and the controller's rulings are listed in README §8 and `.superpowers/sdd/2026-11-06-casheth-build/progress.md` (gitignored, local). Read them before "fixing" something that was deliberately deferred.

## 6. Frontend integration (for the frontend teammate's agents)

- The backend contract for the UI is **`docs/API.md` section 4** (read API, no auth): `GET /events` (audit events, newest last), `GET /agents` (per-agent stats: level, score, tier, on-time %, receivables funded/repaid/defaulted, spend by merchant, lender return), `GET /lenders` (capital, lent, idle, base/boost/blended APR, open strategy hashes), `GET /receivables/:id` (state, funded, lenders owed). All amounts are USDC units as strings (6 decimals).
- Server: `apps/mcp-server` on `http://localhost:4030`. Set `CORS_ORIGINS` to the frontend origin (default `http://localhost:3000`).
- A first integration pass already exists on local branch `worktree-agent-a7984410bf7de54ed` (also pushed as `origin/feat/frontend-integration`): merge of `feat/nextjs-frontend` into main, `frontend/` added to the pnpm workspace as `@casheth/frontend`, an API client with the exact `API.md` types, the landing-page `LiveConsole` wired to `/events` + `/receivables/:id` with 5-second polling and static fallback, 43 passing tests. Build on it or redo it; do not change the backend read API shapes without updating `docs/API.md` and the MCP server tests.
- Gaps the UI does not cover yet: agent stats, lender yield and tiers, evidence links. The data is served; the pages are not built. Keep the teammate's design system; add pages rather than rewriting.
- The frontend `tsconfig` targets ES2017: no BigInt literals; use string math or bump the target deliberately.

## 7. Things not to do

- Do not re-run `scripts/setup-accounts.ts` (destroys `.env.accounts`).
- Do not redeploy or re-wire contracts, dock strategies, or move USDC/HBAR between demo accounts without the owner's go-ahead. Balances are tight and every step is recorded as evidence.
- Do not approve max allowances, do not call `openAndFund` with two schedules, do not write `test: true` probes to the production HCS topic.
- Do not push worktree branches as `main`; do not force-push.
- Do not add dashboards or new frontend pages into the backend apps; the UI lives in `frontend/`.
